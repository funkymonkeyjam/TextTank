# Read-only comparison model (D1)

D1 consumes Foundation TextSnapshot and ReviewChangeSet. Scintilla remains the one mutable authority for every real document. A comparison has two immutable captured texts, never a second editable version of an open document. No apply handle, merge, patch, filter, provider, network or persisted comparison is introduced.

## Capture and lifetime

One MainActor CompareService entry accepts immutable snapshots or explicit source inputs. Resolve document identity before prompts, capture synchronously, then use only Sendable values off-thread. Revalidate identity/revision/reload epoch after awaits and before delivery. Completed stale views remain labelled Out of date; in-flight stale results are dropped. Refresh is explicit and replaces both inputs as one generation; no menu validation, polling or view toggle reads disk/clipboard.

Whole-document capture may resolve a surviving representative after nonfinal view retirement. Selection capture also holds a weak exact originating editor and refuses empty, multiple, rectangular or split-grapheme ranges. The selected slice is freeText plus a parent binding, not a mis-sized DocumentTarget. It inherits the8MiB whole-parent admission. Selection Refresh only uses that same still-live view; retirement disables Refresh until an explicit new source choice. Same-path reopen never retargets a binding. Caret/focus/group/pin operations do not invalidate whole-document bytes.

Select for Compare freezes the clicked document's capture/stamp, with a non-color/accessible tab cue. Compare with Selected uses the marked Original and clicked Modified even when focus differs. Reject missing/closed/stale marks or the same live DocumentID (including clones), including direct service entry. Unbound historical value snapshots may compare versions of one document without Refresh/live-current claims.

File capture uses strict FileCodec and the bounded no-follow regular-file reader,8MiB raw and decoded. Clipboard reads occur only on explicit clipboard Start/Refresh and use the injected runtime capability. AppKit can allocate an offered clipboard representation before admission; input limits are not process-memory bounds. File encoding/BOM metadata is distinct from exact decoded UTF8 text. Only a complete empty change list reports **Byte-identical text**, with decoded-text qualification and visible encoding/BOM metadata.

## Pure projection and resource limits

CompareCore is Foundation-only in TextTankCore; Runtime owns UI, source binding and scheduling. One validated ReviewChangeSet supplies both views. Validate snapshot IDs, bounds, monotonic line-aligned blocks and byte/grapheme highlight boundaries before presentation. Equal logical side slots pair unchanged/changed source lines, with nil for absent-side geometry. Unified rows retain unchanged once and changed original then modified lines. Every content segment names its source range; synthetic gaps, EOF placeholders and collapse summaries contribute no bytes. Reconstruct both inputs exactly, including mixed EOL and missing final newline. Empty input has zero source lines.

F0 default policies/engines/apply semantics stay unchanged. A bounded line-index overload may reuse F0's scanner with explicit caller policy/token/hooks; never silently select the correctness30s profile for UI. D1 projection starts at32m work/2s/128MiB explicit workspace/64MiB output/500000rows. Charge indexing, equality/range checks, grapheme boundaries, construction, collapse and navigation; cancellation polls within1024 charged operations plus documented bounded opaque calls. No huge unmetered line token arrays or quadratic work. Default large inputs may stop explicitly; incomplete never means identical. Inline exhaustion retains complete line results with a separate warning.

Three context lines are shown around changes. The first logical row remains visible, matching Scintilla's unhideable source line zero; fold counts exclude that retained row. Fold only unchanged runs outside their union; accessible summaries expand individually/all. Next/Previous do not wrap (initial Next first/Previous last). Mode switching preserves change ordinal, expansion/whitespace and independent positions without recomputation or I/O.

## Final typed bridge agreement after owned prototype

The owned canonical signed e7748201be2b3c1e9ab9162f768c35026ff320c4 prototype passes17 native assertions: virtual annotations align unequal internal changes, external leading height aligns source line zero, empty engine placeholders add no source bytes, measured wrap-count compensation aligns a subsequent unchanged line, and decoration/fold clear preserves text/revision/savepoint/selections/bookmarks. This is geometry evidence, not physical VoiceOver or a complete D1 window check.

The integrator agrees to the grouped header/implementation helpers now present: comparisonPresentation; selectionIsRectangular; onComparisonViewportChange; comparisonTopDisplayLine, comparisonHorizontalOffset, comparisonDisplayRows and comparisonLineHeight; source/display line, wrap-count and byte-y queries; batched addComparisonHighlights (512ranges/layer), clearComparisonPresentation, virtual gap, hidden-line and whitespace helpers. The independent snapshot owner supplies external leading space and a native scroller; annotations are limited to32760rows per owning source line to avoid the engine's signed-short count overflow. A larger required gap stops presentation explicitly, never inserts bytes. Source line zero remains visible; pure folds omit its logical row. Marker/indicator styles refresh in the existing palette hunk; scroll/zoom callbacks coalesce in the existing notification hunk. No selection-changing scroll API, generic native-message escape hatch, source sharing, Vendor change or application path is approved.

Native geometry integration also uses the typed `comparisonFont` property: its getter reads the source view's style-zero font/zoom without copying text, while its setter works only on independent comparison renderers, synchronizes both pane scales and resets only their view zoom. It uses existing checked font setters. Unified cells retain that same font. This small additive bridge amendment supports the planned zoom/resize geometry and typography obligations; final native checks must verify it together with the existing17-assertion prototype. No real-document font, text, selection or history is set by this property in D1.

Long unified lines use grapheme-safe source segments (normally4KiB, a single cluster at most64KiB), with explicit continuation rows and exact byte reconstruction. This keeps native table cells bounded and their complete content horizontally reachable. Source line numbers and final-newline/EOL labels remain original coordinates. Oversized single clusters stop presentation explicitly; they are never split or repaired. Frame/zoom/collapse changes restore a logical row/subline anchor, not an obsolete display-line index. A failed or cancelled native refresh restores the prior completed captured pair and labels it out of date.

Explicit standalone file encodings are available in the picker; Automatic accepts a Unicode BOM or strict UTF-8 without guessing legacy text. Tab and Saved File uses the document’s last saved encoding by default, pins its saved location and invalidates the captured pair if that location or save state changes during a read. Explicit Refresh resolves the current saved location. Validation and polling perform no file reads.

Native split-view delegates clamp both actual pane frames to240points when the comparison is resized or its divider dragged; the root remains Auto Layout. This is verified after resizing a wider window to the720point minimum. Target-Mac observations include a roughly half-second opaque Scintilla load/shape pause on a2MiB single line; the8ms target applies to explicit row batches, not those opaque operations or process RSS.
