# Native text utilities — implementation and reference limits

The native Text Utilities menu contains deterministic selected-text codecs, a number conversion dialog, configurable hexadecimal encoding, and styled HTML/RTF clipboard/file export. All transformations use the authoritative Scintilla selection and one Undo group. Multiple selections and read-only documents are rejected by the selection-transform UI. Invalid decoding leaves bytes/revision/dirty state unchanged. Decoded bytes must be valid UTF-8; arbitrary binary insertion is not claimed. A leading U+FEFF is content and survives decoding. Input is limited to 16 MiB; SAML inflate output is also bounded to 16 MiB and requires a complete raw-deflate stream.

GPL-3.0-or-later, Don HO; Base64 algorithm comments additionally credit Paul Nankervis. Swift's segment decoding behavior was derived from this source; provenance is retained in the implementation.
- [Converter source](https://github.com/npp-plugins/converter/tree/dbba091853eb27580ea8418bba1c5a907885d211), `source/PluginDefinition.cpp` and `source/conversionPanel.cpp`. GPL-3.0-or-later. This establishes byte-based hex options and unsigned numeric conversion UI. It does not establish which commit is present in the frozen official distribution.
- The pinned Notepad++ installer source establishes the standard inclusion of MIME Tools, NppConverter and NppExport. Their exact bundled binary versions remain unresolved. No Windows plugin was executed.

The inventory's previous eight generic MIME rows missed real options. MIME Tools exposes Base64 unpadded/padded/64-column/by-line encoding, ordinary/strict/by-line decoding; quoted-printable encode/decode; RFC1738/extended/full URL encoding with by-line variants; URL decode; SAML decode. The inspected source does **not** expose SAML encode. The earlier SAML-encode requirement has not been deleted or waived; it requires explicit disposition during reference reconciliation.

## Implemented behavior

- Base64 unpadded, padded, 64-column LF, and per-line encode; ordinary separator-preserving, per-line and strict decode.
- URL RFC1738, extended and full-byte encoding, each with by-line variants; percent decoding retains literal `+`.
- Quoted-printable encoding with CRLF soft wraps and decoding; Unicode is represented by UTF-8 bytes.
- SAML percent/Base64 decoding and bounded raw-deflate decompression, plus direct XML payloads. No XML execution, entity processing or network access occurs.
- UTF-8 byte hex encode/decode, configurable spaces/case/wrap/EOL; unsigned 32-bit binary/octal/decimal/hex conversion with explicit Copy or Insert.
- HTML/RTF snapshots take actual Scintilla style runs, foreground/background/font/bold/italic. A nonempty single selection is exported; no selection exports the whole document. Clipboard includes rich and plain text. File output requires native Save-panel confirmation. HTML is generated by AppKit, so document markup is escaped.

## Deliberate differences and remaining work

These differences remain visible requirements, not parity passes:

- Strict Base64 rejects noncanonical trailing bits/excess padding that the inspected plugin implementation can tolerate. Arbitrary invalid UTF-8 binary output is rejected instead of inserting invalid editor bytes.
- Quoted-printable decoding accepts ordinary LF and NUL content. The reference code has stricter CRLF paths and NUL-terminated buffers; TextTank preserves text rather than reproducing truncation. Golden source/runtime comparisons remain required.
- Hex decoder accepts whitespace between complete pairs, including tab. The source has unusual consistent-space and CRLF rules. Hex option defaults are presented each invocation; option persistence/config-file equivalence remains open.
- Number conversion uses an explicit native dialog, not a continuously synchronized docked ASCII/numeric panel. Binary byte/ASCII control insertion and the panel's full interaction contract remain open.
- Native styled export is implemented, but exact NppExport style/settings/clipboard-flavor semantics and exported-file UI are not certified against a frozen plugin binary. AppKit representation of NUL and all exotic style attributes needs focused cases.
- SAML decode uses the system zlib raw-deflate API and explicit complete-stream/size validation; its limits and XML-prefix checks are not asserted identical to the plugin's `tinf` implementation.
- Physical Save-panel/clipboard walkthrough, enormous-input responsiveness, complete macro integration and all reference differences remain unverified.
