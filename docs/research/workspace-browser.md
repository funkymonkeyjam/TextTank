# Workspace browser implementation evidence

`WorkspaceBrowserController` provides native Open Documents, Folders and Recent Files views, a lazy expandable folder tree, Add/Remove Folder, Refresh and explicit Open. Removing a root only changes workspace configuration; it never deletes files. The menu provides a recent-file submenu. Existing dirty documents are focused/reused without reload.

`WorkspaceBrowserStore` persists versioned folder/recent identities through the private regular-file store. It never automatically opens document paths or executes imported content. Invalid or unsupported stored data is preserved; mutation is blocked until the configuration is repaired or moved. Opening an ordinary document can still succeed, with a visible recent-history persistence error.

Folder enumeration is bounded to 2,000 entries per directory in the UI. Hidden entries, symbolic links and special files are skipped, with skipped/truncated status. The directory descriptor is shared by enumeration and no-follow metadata checks. Opening reads a regular file once through the nonblocking descriptor guard, then hands the captured bytes to NSDocument; it does not preflight and then reopen a possible FIFO by pathname. Decode failure registers no document.

Author native suite: `Tests/WorkspaceBrowserChecks.swift`, **35 assertions passed**. Tests use isolated temporary directories/configuration and disable OS recent-history writes through the injected `recordsSystemRecent` flag. They cover persistence, duplicate roots/history, invalid configuration preservation, symlink/FIFO skipping/rejection, listing cap, Unicode document opening, reuse of dirty documents after external change, malformed text, native panel/menu, non-destructive root removal, background unchanged/changed/missing detection, no automatic reload, dirty/stale reload rejection and explicit clean reload. A review-found corrupt-config overwrite was repaired before this result. Independent reviewer: search worker; corrupt-state preservation repair and monitor generation/revision/attachment guards source-reviewed with no remaining concrete blocker.

The Workspace menu includes Monitor Current File and a separate Reload Monitored File action with confirmation. Monitoring polls one saved document every two seconds using a background regular-file read capped at 32 MiB. Main-thread completion checks the document identity, file URL, editor revision, saved fingerprint and monitoring generation before publishing status. It never changes editor text, including dirty documents. Closing the document stops monitoring; files above the cap report an explicit limitation. The reload action rejects dirty, detached or revision-changed documents. The byte cap is not an I/O deadline: a stalled filesystem read cannot be forcibly cancelled, and one outstanding read retains its document until completion. This is polling rather than tail-follow mode; large-file monitoring, automatic refresh and watch persistence are not claimed.

This is a useful partial workspace implementation, not full project parity. Named multi-project workspaces, explicit file membership, project file-membership search, moved-file resolution, automatic document-list refresh, full panel/tab/window persistence and complete keyboard/VoiceOver behavior remain open. Directory refresh/open currently run synchronously; network-filesystem and large-directory responsiveness are not certified. Physical GUI interaction remains separate from native object tests.
