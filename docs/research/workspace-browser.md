# Workspace browser implementation evidence

`WorkspaceBrowserController` provides native Open Documents, Folders and Recent Files views, a lazy expandable folder tree, Add/Remove Folder, Refresh and explicit Open. Removing a root only changes workspace configuration; it never deletes files. The menu provides a recent-file submenu. Existing dirty documents are focused/reused without reload.

`WorkspaceBrowserStore` persists versioned folder/recent identities through the private regular-file store. It never automatically opens document paths or executes imported content. Invalid or unsupported stored data is preserved; mutation is blocked until the configuration is repaired or moved. Opening an ordinary document can still succeed, with a visible recent-history persistence error.

Folder enumeration shows at most 2,000 entries per directory in the UI. The directory is read (up to 20,000 entries) and sorted before that limit applies, so a truncated listing is the first entries in display order. Hidden entries, symbolic links and special files are skipped, with skipped/truncated status, and do not count toward the limit. Adding a folder that is a symbolic link is refused with a message that says so. Saved folders and recent files are compared by standardized path everywhere. The directory descriptor is shared by enumeration and no-follow metadata checks. Opening reads a regular file once through the nonblocking descriptor guard, then hands the captured bytes to NSDocument; it does not preflight and then reopen a possible FIFO by pathname. Decode failure registers no document. A file whose first bytes could be UTF-32 or UTF-16 LE text starting with NUL gets the same explicit "Open as UTF-16 LE" offer as File > Open.

Author native suite: `Tests/WorkspaceBrowserChecks.swift`, **35 assertions passed**. Tests use isolated temporary directories/configuration and disable OS recent-history writes through the injected `recordsSystemRecent` flag. They cover persistence, duplicate roots/history, invalid configuration preservation, symlink/FIFO skipping/rejection, listing cap, Unicode document opening, reuse of dirty documents after external change, malformed text, native panel/menu, non-destructive root removal, background unchanged/changed/missing detection, no automatic reload, dirty/stale reload rejection and explicit clean reload. A review-found corrupt-config overwrite was repaired before this result. Independent reviewer: search worker; corrupt-state preservation repair and monitor generation/revision/attachment guards source-reviewed with no remaining concrete blocker.

The Workspace menu includes Monitor Current File and a separate Reload Monitored File action with confirmation. Monitoring polls one saved document every two seconds on a background queue, capped at 32 MiB. A poll opens the file without following links, takes its metadata and closes it; the file is read and hashed only when the device, inode, size, modification time or change time differs from the last settled sample. A sample is settled when both times were more than two seconds old when it was taken, so a file written moments ago is hashed on every poll until then. Main-thread completion checks the document identity, editor window and monitoring generation, then drops the sample if the file URL, editor revision or saved fingerprint changed meanwhile, before publishing status. A Save As is followed to the new file. Status is published once per change and shown on its own line in the panel, apart from the refresh, listing and error messages. It never changes editor text, including dirty documents. Closing the document stops monitoring; files above the cap report an explicit limitation. The reload action rejects dirty, detached or revision-changed documents. A document keeps the SHA-256 of the bytes last read or saved, not a copy of them. Save reads and hashes the file before overwriting it unless the file still has the settled metadata recorded when it was last read; after a save the metadata is never trusted until a later hash confirms it. Check for External Changes always hashes. The byte cap is not an I/O deadline: a stalled filesystem read cannot be forcibly cancelled, and one outstanding read retains its document until completion. This is polling rather than tail-follow mode; large-file monitoring, automatic refresh and watch persistence are not claimed.

This is a useful partial workspace implementation, not full project parity. Named multi-project workspaces, explicit file membership, project file-membership search, moved-file resolution, full panel/tab/window persistence and complete keyboard/VoiceOver behavior remain open. Directory refresh/open currently run synchronously; network-filesystem and large-directory responsiveness are not certified. Physical GUI interaction remains separate from native object tests.

The Open Documents list reloads when a document window closes or becomes main while the panel is visible, and after the browser opens a file; it does not rewrite the status line. The edited marker on a row is still only as fresh as the last reload. The panel drops its document list when it closes. Expanded folders are remembered by path and expanded again after Refresh or a change of view.

Open Session Snapshot shows its first prompt from the session file alone. The referenced originals are read only after Check Originals…, on a background queue behind a Cancel prompt, hashed in 64 KiB steps through the same no-follow regular-file open; the prompt then returns with one status line per document. The session file itself is still read on the main thread, and a session with many documents still produces a long prompt.
