# Foundation review model (F0)

Foundation is headless shared infrastructure. Scintilla remains the sole mutable text/Undo authority. There is no comparison UI, provider, implicit clipboard/network capture, persisted review format or migration of existing consumers. DS-90-92, DS-97 and DS-100-101 apply; existing UI and design budgets stay unchanged.

Immutable Sendable TextSnapshot holds strict decoded UTF8, SourceIdentity, a unique SnapshotID, a document's revision/loadEpoch stamp, display label and optional FileFormat. Clones share runtime DocumentID, never view/path identity. Ranges name a particular snapshot and are half-open UTF8 byte spans. Exact EOL-preserving lines join to the input; complete change blocks replay to the modified bytes. Empty input has zero lines, with no phantom trailing record. Preserve leading U+FEFF and NUL; file transport BOM/encoding belongs to FileFormat.

MainActor capture synchronously copies bounded editor bytes/revision/epoch and retains only a weak exact TextDocument context. Background workers receive immutable values. Disk capture uses the bounded no-follow regular-file reader and strict FileCodec; clipboard capture is explicit. Resolve surviving representative after nonfinal view retirement; reject final close, same-path reopen, revision change or identical-byte reload. Focus/caret changes never retarget explicit byte proposals. Existing selection-sensitive automation behavior is untouched.

Two first-party line strategies share one budget: prefix/suffix-trimmed bounded Myers, and unique exact-line anchors/LIS with bounded Myers gaps. Hash collisions require byte verification. Account all scans, sorting, trace/backtrack, workspace, output and gap work; use bounded storage rather than quadratic retained trace. Cancellation is polled within1024 charged primitive operations plus bounded opaque calls. Complete/cancelled/budgetStopped are explicit; incomplete results never mean identical and cannot issue proposals. Late cancellation/invalidation drops delivery. Inline refinement has one separate aggregate budget and may leave exact complete line blocks unrefined. Refined display spans respect full grapheme clusters.

Starting policy:8MiB decoded per input (16MiB pair),8MiB raw file,250000 lines/input;128m line work units/2s/128MiB explicit workspace/100000 blocks/32MiB output. Frozen required correctness corpus uses a separately selected512m/30s profile with unchanged memory/output caps and must complete in both engines; never silently retry with a larger budget. Inline:250000 units/250ms/16MiB workspace/32000 spans/8MiB output,64KiB combined block admission and32000 aggregate grapheme tokens. Resource limits are provisional, measured in F0 evidence, not product promises. Test-machine scale never raises hard guards. Capture/decode/transient buffers and process RSS are separate from workspace estimates.

Proposal admission:<=10000 edits;<=8MiB aggregate expected bytes;<=8MiB replacements;<=8MiB final document;64m validation units. Check overflow-safe metadata/counts before deep copies/conversion and before no-op filtering. Native reverse application may transiently hold current+replacement bytes (<=16MiB before capacity/Undo overhead). Pure preflight validates target stamp, strict current/replacement UTF8, expected bytes, scalar boundaries and every ordered/nonoverlapping range before mutation. Starts strictly increase; adjacent positive ranges are valid. Duplicate zero-width/shared-start or insertion-at-another-end combinations reject; callers explicitly coalesce first. Never relocate a proposal.

An internal MainActor ReviewRequest issues one shared reference apply ticket for its private fresh ProposalID. Copies share consumption. Pure preflight may repeat; first actual apply consumes all outcomes, including malformed/closed/readOnly/stale/cancelled/budget/no-op rejection. Second/reentrant apply reports alreadyUsed before editor access. No public old-ID ticket reissue or unbounded permanent tombstone set.

Actual apply revalidates weak exact document identity, open membership, shared readOnly, revision/epoch and live bytes on MainActor. Convert every effective replacement exactly before mutation; no await/modal/selection/focus gap. Call existing applyEdits(expectedRevision:expectedLength:) with sorted effective edits; it owns the single Undo group, so do not nest one. No selection staging or new bridge API. Validate all edits before filtering byte-identical edits. Empty effective batch returns noChange without bridge/revision/Undo/savepoint/selection churn. All rejection preserves text, every view's oriented selections, revision, dirty/savepoint and prior Undo/Redo. One Undo/Redo through either clone restores/reapplies the batch exactly.

Pure review sources belong explicitly to TextTankCore; capture/request/applier belong to Runtime. Tests import the actual canonical signed modules and compile Tests sources only. Preserve all51 existing suites/seven document processes. New layering/Core/applier suites, exact corpus, budget/cancellation/lifetime/native rejection cases and two-strategy measurements must pass independent fresh verification. Maximum two formal product repair rounds. No TESTING flags, skips, looser deadlines or raised design/performance budgets.

After accepted F0, deliver the verified latest Release safely and preserve historical evidence. Stop after Foundation. Later D1/A1/A2/U1 and other capabilities need separate authorization. This contract records implementation intent; actual outcomes belong to acceptance evidence, not this document.
