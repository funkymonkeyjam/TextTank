# TextTank: remaining application, one continuous build

Prepared 14 November 2026. This is the execution plan for finishing the existing application. It preserves the original full-capability contract and supersedes the old milestone-by-milestone handback approach. It does not certify the application as complete or promise that the work fits in one model context.

## Execution contract

Run implementation, integration, tests, independent review and repairs as one continuous job. Advance automatically through the internal work packages below. Do not return control merely because a package, feature, commit, build or CI run is green. Preserve checkpoints so context compaction or an interrupted tool session can resume without restarting the work. Give concise progress reports; routine engineering decisions need no approval.

The endpoint is a launchable, tested local review build, curated pushed source, an unmerged PR, an evidence-backed capability ledger, exact run instructions and a short review walkthrough. Keep all standard Notepad++ requirements in scope. A genuine environment, permission or unavailable-reference blocker must be recorded precisely; finish independent work before surfacing it. Never convert an unverified requirement into a pass to satisfy the endpoint.

Reuse `implementation/native-mac` and PR 1 in `funkymonkeyjam/TextTank`. Do not recreate the repository, rewrite history, merge, tag a release, buy services, require a paid signing account or publish to an app store. Do not overwrite user documents or use live personal data as test fixtures. Keep the already working recipe workflow available throughout development.

## Locked architecture and scope

- Native Swift/AppKit with a narrow Objective-C++ bridge, Scintilla Cocoa and Lexilla. Keep the pinned engines until a documented dependency change is required; audit Notepad++ deltas explicitly.
- One authoritative Scintilla text model and undo history. NSDocument owns identity, save/revert, dirty state and recovery. Shared clones never become independent editable copies.
- Editor/UI access stays on the main thread. Background work captures revision and selection, reports progress and cancels cooperatively; stale results never overwrite newer edits.
- TextTank/Carbon Caret identity is adopted. Keep native control typography, readable light/dark appearances and the existing icon provenance. Do not reopen naming research.
- Free core and shipped features, offline ordinary editing and deterministic automation, no required account or paid API. Optional AI is outside this completion run unless already present in the frozen standard requirements.
- macOS 14 minimum, arm64 primary review target. Verify the minimum OS in an actual available runtime. Build a universal binary only if both slices work, and label Intel runtime evidence separately. Never raise the OS minimum to make the build easier.
- Full standard reference capabilities include bundled utilities and functional Mac equivalents for platform-specific integrations. Windows DLL compatibility is not promised; a named, tested Mac equivalent must account for each applicable behavior.

## Team and integration discipline

Use one integrator and at most three simultaneous workers. The integrator owns dependency pins, shared project/build files, bridge API, document lifecycle, command catalog and cross-feature integration. Assign disjoint paths, behavior IDs, dependencies and expected tests to each worker. Rotate workers among search/editor, languages/workspace and automation/utilities as dependencies clear. Reserve independent review capacity at every risky integration; the author cannot self-certify the review.

Before starting a work item, record the expected behavior, owning paths and minimal regression that can fail. Implement a vertical slice into actual native controls, then test and review it. Integrate small coherent commits; rerun affected suites and the full suite at meaningful integration points. Do not run repeated full suites when nothing changed. Reject placeholder handlers, disabled-menu substitutes, TODO-based completion and broad “supported” labels without behavior evidence.

If a worker finds a defect, report the failing fixture and affected contract, repair it and have another reviewer examine the fix. If a shared contract changes, the integrator updates consumers and reruns affected tests. Preserve the working package separately from in-progress code so the user can still launch a known build.

## Verification details that must not fall between packages

1. **Text integrity:** UTF-8/UTF-16 byte offsets, composed/decomposed characters, emoji/ZWJ, FEFF as content versus BOM, NUL, CR/LF/CRLF, malformed bytes, legacy encodings, empty/huge/long-line buffers, read-only locations and cancelled native panels.
2. **Lifecycle:** several dirty documents, two views of one document, closing either view first, Save/Discard/Cancel during Quit, cancelled multi-document quit, reopening sessions, corrupted recovery files, disk-full/permission/rename faults, external edits and app termination. Keep the actual detached-document Quit-crash regression.
3. **Search:** bounded work and visible cancellation; unchanged dirty documents when navigating stale results; result caps and skipped files; symlink/FIFO/path-alias behavior; replacements racing external modifications. Define measured cancellation and performance budgets before signoff; do not claim instantaneous cancellation through an uninterruptible decode.
4. **Automation/Reminders:** full, unedited ingredient-list copies from available recipe sites pasted through the app; Markdown/plain/rich clipboard forms; quantities/fractions/alternatives and duplicate retention; absent/revoked access; read-only/deleted/moved lists; uncertain writes; intentional resend versus accidental duplicate; restart journal reconciliation. Successful user transfer closes only the observed happy path. Use an explicitly designated scratch list for additional live mutation; ask only if that required resource/permission is missing.
5. **Performance:** pin fixture generators and host/toolchain; measure open, scrolling, find, replace, save, recovery and cancellation on 1/10/100 MiB files, a single long line and 100 tabs where feasible. Record time, peak memory and responsiveness. Establish ceilings from measurements and the native UX contract, then enforce them; crashes, silent truncation and unbounded memory growth are failures regardless of speed.
6. **Platform/accessibility:** actual minimum-supported macOS runtime, current host and CI are distinct evidence; cross-compilation is not runtime testing. Exercise CJK IME, dead keys, keyboard-only navigation, VoiceOver, focus restoration, scaled text, light/dark/high contrast and production icon variants. If a runtime is unavailable, keep that validation open and finish independent work.
7. **Distribution:** clean pinned dependency fetch, source/build/license correspondence, privacy review of tracked paths, exact-head CI, archive extraction/signature validation and actual launch outside synced-file metadata interference. Ad-hoc signing supports local review; notarization is separate and is not a paid prerequisite for this task.

## Completion gate and reporting

Every required normalized behavior and automation acceptance row must contain its implementation paths, concrete cases, observed evidence, reviewed differences and candidate identity. Deduplicate aliases with explicit mappings; never drop a requirement. A platform adaptation needs a documented functional equivalent. Tests passing at the core layer do not prove menu wiring or a complete user journey.

Run the independent review/repair loop until there are no unresolved blocking findings and the required behavior ledger is satisfied. Final delivery must distinguish implemented-and-verified, implemented-but-unverified and blocked/missing behavior. If any required behavior remains missing or unverified, label the build incomplete and state the actual blocker; do not claim completion or stop simply because further implementation is substantial.

Durable progress belongs in the existing task ledger, capability records, `harness/state.json`, review reports and ignored observed logs. Record active work, exact next action, branch/tree identity, ownership, failures and the latest launchable package at each interruption. Resume from those records automatically when execution continues. Internal checkpoints are recovery points, not requests for user approval.

Final review walkthrough: open/edit/save a Unicode file; exercise clone/Undo; regex search/replace and folder results; column editing; language/UDL/completion/function navigation; session restoration; a named recorded macro; rename/run a configured automation; paste full recipe ingredients, clean in place and explicitly send to Reminders; customize a shortcut; print/export; close and quit dirty documents through Save/Discard/Cancel. Verify the delivered package, not only the development binary.
