# Preview fixtures

Inputs and expected outputs for `Tests/PreviewCoreChecks.swift` (`scripts/test-preview.sh`). No check edits a fixture at run time. The behaviour they pin is described in `docs/preview-model.md`.

## `markdown/`

Each `name.md` is rendered by `MarkdownRenderer` and compared byte for byte with `name.html`. The suite finds the pairs by listing the folder, so a new pair is picked up without a code change.

The expected files are *derived*: they were produced by the renderer and then read line by line against the CommonMark and GitHub table rules and the documented differences (raw HTML escaped, restricted link addresses). They pin the output; they are not independent evidence that it is correct. The independent evidence is in the suite itself: the table of small inputs whose expected HTML is taken from the CommonMark specification's examples, and the structural check that every rendered output consists only of the renderer's own tags, with known attributes and permitted addresses.

| Pair | Covers |
| --- | --- |
| `headings` | ATX and setext headings, closing hashes, the indentation limit |
| `paragraphs` | soft and hard line breaks, backslash escapes, entities, escaped raw HTML |
| `emphasis` | `*` and `_`, nesting, intraword rules, unmatched runs |
| `code` | code spans, backtick and tilde fences, info strings, indented code, an unterminated fence |
| `quotes` | block quotes, nesting, lazy continuation, a fence inside a quote |
| `lists` | bullet and ordered lists, nesting, tight and loose, task items, lazy lines, tabs |
| `links` | inline, reference and autolinks, images, titles, refused addresses |
| `references` | reference definitions: forward, case-insensitive, in a quote, malformed |
| `tables` | alignment, short and long rows, escaped pipes, a table after a paragraph, non-tables |
| `breaks` | thematic breaks and what is not one |
| `whitespace` | tabs as indentation and as content (the file contains tab characters) |
| `line-endings` | CRLF and CR line endings (the file contains carriage returns and has no final line break) |
| `unicode` | non-ASCII text, right-to-left text, emoji, no-break spaces around emphasis |
| `adversarial` | unbalanced brackets and emphasis, forty-deep quotes, lists and brackets, an unterminated fence |

Large adversarial inputs (hundreds of kilobytes of one construct, a two-mebibyte document, a five-mebibyte JSON array) are generated by the suite and are not stored here.

To regenerate one expected file after an intended change to the renderer, run the suite: a mismatch writes `preview-<name>.actual.html` to the test artifacts folder (`build/tests`). Read the difference before copying it over the expected file.

## `html/`

Inputs for `StaticHTMLPolicy.prepare`. The expected insertion point, external references and script counts are stated in the suite.

- `tricky.html`: uppercase tags, unquoted attributes, a `<head>` inside a comment and inside an attribute value, a script containing `<` and markup, CDATA, `srcset`, `@import` and `url()` in a style element and a style attribute, event handlers, a `javascript:` link, a `<base>` tag, and an unterminated script at the end.
- `plain.html`: a page with only local resources; its report is empty.
- `no-head.html`, `doctype-only.html`, `fragment.html`: documents without a `<head>`, for the three places a head is created.

## `svg/`

- `plain.svg`: nothing external.
- `hostile.svg`: scripts, an event handler, external images, a `use`, a style import in CDATA, and a link (which is not a loaded resource).
- `not-svg.xml`: XML whose first element is not `svg`.
- `prefixed.svg`: a namespace-prefixed `svg:svg` root after a comment.

## `delimited/`

- `values.csv`: quoted commas, doubled quotes, a line break inside quotes, leading zeros, a formula, padding and empty cells.
- `ragged.tsv`: rows of different lengths and a tab inside quotes (the file contains tab characters).

## `json/`

- `sample.json`: every JSON form, numbers that no numeric type can hold, escapes including a surrogate pair and a lone surrogate (written as backslash escapes; keep them that way), a non-ASCII name, a duplicated name and nested containers. The suite also parses every prefix of this file.
